1 Tổng quan & Sơ đồ quan hệ

Hệ thống liên kết kết nối ba thực thể nghiệp vụ theo quan hệ nhiều-nhiều (M:N), cho phép tra cứu chéo giữa các văn bản pháp luật, nghiên cứu pháp lý và các hồ sơ vụ án thực tế.

Quan hệ M:N đối xứng: Mỗi entity có thể link đến nhiều entity kia. Một Case Reference có thể áp dụng cho nhiều vụ án; một vụ án có thể tham chiếu nhiều văn bản; một Legal Study có thể phân tích nhiều văn bản và được dùng trong nhiều vụ án.

3 JsLegalReferenceLinks — Liên kết từ Case Reference

Component hiển thị trong tab của trang chi tiết một Case Reference record. Cho phép xem tất cả Cases và Legal Studies liên quan, thêm link mới.

FEAT-01 Load danh sách liên kết (LegalReferenceLinksViewer)
Luồng load
  • Lấy legalReferenceId từ ctx.record / URL / ctx.params / route filterbytk
  • Fetch legalReference:get?filterByTk={id} với đầy đủ appends (cases, projects, caseReferences, legalStudy, legalStudies...)
  • Parallel: getCaseRowsFromReferenceRecord() + fetchLegalStudyRowsForReference()
  • Merge, dedup bằng uniqById() + uniqLinks()
  • Sort theo updatedAt DESC
  • Resolve tên người tạo qua users:list
API calls
  • GET legalReference:get?filterByTk=ID
  • GET legalReference:list filter referenceKind=legal_study (source rows)
  • GET folders:list filter storageType=legal_study + legalReferenceId
  • GET documents:list tương tự
  • GET users:list batch resolve names
UI
  • Loading spinner khi đang fetch
  • Alert lỗi kèm nút Reload nếu fail
  • Table với header: Type | Code/Name | Description | Creator | Updated | ⟶
  • Row click → mở tab mới đến detail URL
  • Empty state nếu chưa có link

fetchLegalStudyRowsForReference() — chiến lược 3 nguồn

// Nguồn 1: legalReference:list với filter referenceKind = "legal_study"
//          → lọc tiếp những record có legalReferenceId match
fetchLegalReferenceSourceRows(legalReferenceId)

// Nguồn 2: folders:list với storageType=legal_study + legalReferenceId filter
//          → fallback sang broad filter nếu direct filter fail
fetchLegalStudyScopeRowsForReference("folders:list", legalReferenceId)

// Nguồn 3: documents:list tương tự
fetchLegalStudyScopeRowsForReference("documents:list", legalReferenceId)

// Merge và dedup bằng ID
uniqById([...sourceRows, ...folderRows, ...documentRows])

  • Options dropdown cũng ẩn những case đã link
FEAT-03 Thêm link Legal Study ↔ Case Reference

  • Segment toggle: Linked Case | Legal Study
  • Select Legal Study với search tên/code
  • Loại bỏ studies đã link (linkedLegalStudyIds)
API — 18 candidates
  • legalReference/{refId}/legalStudy:add
  • legalReference/{refId}/legalStudies:add

6 Chiến lược API Fallback

Do Nocobase collection names và relation field names có thể biến thể (singular/plural, PascalCase/camelCase), cả hai JS component đều dùng pattern candidate fallback.

FEAT-10 postRelationCandidates() — thử đến khi thành công 
const postRelationCandidates = async (candidates) => {
  let lastError = null;
  for (const candidate of candidates) {
    // Thử payload { tk: id } trước, rồi { tks: [id] }
    for (const data of [{ tk: targetValue }, { tks: [targetValue] }]) {
      try {
        const response = await ctx.api.request({ url: candidate.url, method: "POST", data });
        return getResponseData(response); // thành công → dừng
      } catch (error) {
        lastError = error; // tiếp tục thử candidate tiếp theo
      }
    }
  }
  throw lastError; // tất cả fail → throw lỗi cuối cùng
};

fetchWithCandidates() — thử nhiều endpoint name

const fetchWithCandidates = async (urls, params) => {
  for (const url of urls) {
    try {
      return activeRows(await fetchAllList(url, params));
    } catch { /* thử url tiếp theo */ }
  }
  throw new Error("No API candidate worked");
};

// Ví dụ: legalReference candidates
["legalReference:list", "legalReferences:list", "LegalReference:list"]
fetchAllList() — auto pagination: Tự động fetch nhiều trang cho đến khi hết data (max 20 trang), dùng meta.totalPage / meta.count để dừng đúng lúc. pageSize mặc định = 200.
FEAT-11 getCurrentLegalReferenceId() — resolve ID từ nhiều context 
const getCurrentLegalReferenceId = (record) =>
  extractId(record?.id)                        // từ ctx.record
  || extractId(ctx.recordId)                    // Nocobase recordId
  || extractId(ctx.filterByTk)                  // filter param
  || extractId(ctx.params?.filterByTk)          // nested params
  || extractId(ctx.router?.params?.filterByTk)  // router params
  || extractId(ctx.view?.params?.filterByTk)    // view params
  || extractId(ctx.inputArgs?.filterByTk)       // inputArgs
  || extractId(getRouteFilterByTk());           // URL path parsing

// getRouteFilterByTk(): regex match /filterbytk/([^/?#]+)/ từ window.location.pathname

Relation resolution — valueMatchesId()

Hàm kiểm tra một field value có match một ID hay không, xử lý các dạng dữ liệu Nocobase trả về:

Dạng valueXử lý
Số nguyên: 123So sánh trực tiếp với ID
Chuỗi: "123"So sánh String(extractId(value)) === String(safeId)
Object: { id: 123, name: "..." }extractId(value) → lấy .id
Array: [{ id: 123 }, { id: 456 }]relationRows(value).some(...)
Nocobase pagination wrapper: { data: { data: [...] } }relationRows() unwrap

Normalize ID — normalizeFilterId()

Chuyển đổi ID từ string về number khi có thể, để tránh filter mismatch giữa "123" và 123:

const normalizeFilterId = (id) => {
  const safeId = Number(id);
  return Number.isFinite(safeId) && String(safeId) === String(id) ? safeId : id;
  // "123" → 123, "abc" → "abc", "12.5" → "12.5" (giữ nguyên)
};
