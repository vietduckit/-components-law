2. Module 1 — All Task Block

📋 AllTaskBlock.js

Danh sách tổng hợp toàn bộ công việc (task & subtask) của công ty luật. Hỗ trợ 3 view mode: Table (có group & column config), Board (kanban theo status), Roadmap (Gantt theo tháng). Scope "my" giới hạn về assignee là luật sư của current user.

2.5 Column Menu & Actions

Mỗi header cột (trừ actions) có nút "•••" mở Popover 270px:

  • Select column — highlight cột (visual only)
  • Sort ascending / descending — active button = primary. Chỉ một cột được sort tại một thời điểm.
  • Clear sort — chỉ hiện khi cột đang sort
  • Filter by values — multi-select dropdown; options = unique display values từ in-memory rows
  • Group by values — disabled nếu field không trong GROUP_BY_OPTIONS
  • Hide field — disabled cho locked columns
  • Move left / Move right — reorder trong columnOrder
  • ✕ Clear column config — xóa filter, sort, group-by của cột này

Header hiển thị:

  • Màu nền primary-light khi cột đang được sort hoặc filter
  • Drag handle (8px, col-resize cursor) cho column resize — pointer capture, min width 90px

2.7 View Modes

Table mode (default)

  • Hiển thị mỗi group là một section card với header màu và AntD Table bên trong
  • Table có scroll: { x: totalColumnWidth } — horizontal scroll khi columns vượt chiều rộng
  • Pagination theo group (5 groups/trang)
  • Mỗi table trong group có AntD pagination row-level (10 rows/trang, ẩn khi ≤ 10)

Board mode (Kanban)

  • 7 cột theo status (không theo groupBy setting)
  • Cards: title link, project, assignee, due date
  • Drag-and-drop: draggable, onDragStart → onDrop → API update status → reload
  • Scroll ngang (overflow-x: auto), height calc(100vh - 260px) max 680px min 360px
  • Filter bar ẩn "Group by" khi board mode

Roadmap mode (Gantt)

  • Chỉ tháng hiện tại
  • Left: danh sách task (title + assignee), Right: timeline
  • Timeline có mật độ biến: recent days hiển thị riêng lẻ, ngày cũ hơn gom thành nhóm 5
  • Bar: viền đỏ + nền #fff1f0 nếu overdue; màu primary nếu bình thường
  • Tasks không có ngày: placeholder "Outside {Month}"
  • Không paginate — render ALL groups/rows

3.5 Approve / Reject Flow

Approve Flow

1
Guard kiểm tra

Nếu approvingKey === row.key → return ngay (chặn double-click). Set approvingKey = row.key.

2
Xác định collection

row.recordType === "subTask" → subTasks, ngược lại → tasks.

3
API call

POST {collection}:update?filterByTk={id} với body { status: "approval", approvedById: currentLawyerId }.

Note: approvedById chỉ được gửi khi currentLawyerId là truthy.

4
Success

message.success("Task approved successfully.") → reload() (full reload, không optimistic update).

5
Error / Finally

Error: message.error("Could not approve task."). Finally: setApprovingKey(null).

Reject Flow

1
Mở modal

openRejectModal(row) → setRejectModal({ open: true, row, reason: "", submitting: false }).

2
Validation

reason.trim() phải không rỗng → message.warning("Vui lòng nhập lý do từ chối.") nếu vi phạm.

3
API call

POST {collection}:update?filterByTk={id} với body { status: "toDo", rejectionReason: reason.trim() }.

4
Success

message.success("Task rejected and returned for revision.") → đóng modal → reload().

5
Error

message.error("Could not reject task.") → submitting = false (modal giữ nguyên để user retry).
