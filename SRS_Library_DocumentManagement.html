1 Tổng quan hệ thống

4 Hệ thống phân quyền

Phân quyền hoạt động ở cấp thư mục, kế thừa đệ quy từ thư mục cha lên đến gốc. File-level sharing (documentShares) là lớp bổ sung độc lập.

FEAT-01 Vai trò & Ma trận quyền
Logic — roleToPerms()
  • admin: mọi quyền, bỏ qua permission check
  • owner: người tạo folder, toàn quyền trên folder đó
  • manager: quản lý permission, move, delete
  • editor: tạo, đổi tên, không xóa/move
  • viewer: chỉ xem
DB Collections
  • folderManagers: userId + folderId (role: manager)
  • folderMembers: userId + folderId (role: editor/viewer)
  • lawyers: thông tin luật sư (link với users)
  • users: Nocobase built-in users
QuyềnAdminOwnerManagerEditorViewer
Xem file✓✓✓✓✓
Tạo folder/file✓✓✓✓—
Đổi tên✓✓✓✓—
Di chuyển✓✓✓——
Xóa (trash)✓✓✓——
Chia sẻ file✓✓✓✓—
Quản lý phân quyền✓✓✓——
Xóa vĩnh viễn✓✓✓——
Kế thừa quyền: Hàm getFolderPermissions(folder, user, allFolders, currentLawyerId) đệ quy lên thư mục cha cho đến root để tìm ra vai trò áp dụng. Nếu không tìm thấy role nào → quyền tối thiểu (viewer hoặc no-access tùy cấu hình space).
FEAT-02 Giao diện quản lý phân quyền thư mục
UI
  • Modal "Phân quyền thư mục" mở từ context menu folder
  • Danh sách managers + members hiện tại
  • Dropdown chọn user, dropdown chọn vai trò (Manager/Editor/Viewer)
  • Nút "Thêm" — ghi vào DB ngay
  • Nút xóa từng permission entry
DB
  • Thêm: POST folderManagers:create hoặc folderMembers:create
  • Xóa: DELETE folderManagers:destroy / folderMembers:destroy
  • Đọc: GET folders:get với appends ["folderManagers","folderMembers"]
Activity Log
  • Ghi permission_updated vào activity_log sau mỗi thay đổi permission
  • Ghi thủ công từ JS (trigger SQL không cover được context này)

5 Quản lý Thư mục

FEAT-03 Tạo thư mục mới
UI
  • Nút "+ Thư mục mới" trong topbar
  • Popconfirm / inline input trong topbar hoặc Modal nhỏ
  • Input field tên thư mục; nút Hủy / Tạo
  • Sau tạo: folder xuất hiện ngay trong grid (optimistic UI)
  • Lỗi đã fix: bỏ onPressEnter khỏi Input để tránh double-submit
DB
  • POST folders:create
  • Payload từ buildScopedPayload(activeSpace): storageType, moduleScope, parentFolderId (nếu tạo con)
  • Field createdById tự động ghi bởi Nocobase
WF / Trigger
  • Trigger SQL fn_log_activity_documents() ghi action: "created" vào activity_log
  • JS không cần ghi log thủ công cho thao tác này
FEAT-04 Đổi tên / Di chuyển / Xóa thư mục
UI
  • Context menu (3-chấm) trên mỗi folder card: Đổi tên, Di chuyển, Xóa
  • Đổi tên: inline editable text hoặc modal input
  • Di chuyển: TreeSelect chọn thư mục đích
  • Xóa: Popconfirm xác nhận → soft delete
DB
  • Đổi tên: PATCH folders:update với { name }
  • Di chuyển: PATCH với { parentFolder: targetId }
  • Xóa: PATCH với { isDeleted: true, deletedAt: now } (soft delete)
Bảo mật
  • Check canRename, canMove, canDelete trước khi show menu item
  • Ẩn button nếu không có quyền (không chỉ disable)
  • Khi move: kiểm tra không move folder cha vào con (circular)
FEAT-05 Breadcrumb navigation
UI
  • Breadcrumb hiển thị path đầy đủ: "Knowledge Base / Hợp đồng / 2025"
  • Click bất kỳ node → navigate đến folder đó
  • Root node hiển thị tên space tương ứng
Logic
  • Tính từ selectedFolderId → tra folders[] → follow parentFolder chain
  • useMemo để không tính lại khi folders không đổi
  • Root name map theo activeSpace

  • Hỗ trợ multiple files cùng lúc
